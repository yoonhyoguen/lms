# LMS 과제 제출·채점 시스템 — 주요 개발 핵심내용

윤효근 · 자바 스프링 중간고사 프로젝트 · GitHub `yoonhyoguen/lms`

---

## 1. 무엇을 만들었나

**강사가 과제를 내고, 학생이 제출하고, 강사가 채점하는 웹사이트**입니다.

```
강사: 강좌 개설 → 참여코드 발급 → 과제 등록 → 제출 현황 확인 → 채점 → 통계
학생: 회원가입 → 참여코드로 수강 등록 → 과제 확인 → 기간 안에 제출 → 점수·피드백 확인
```

| 구분 | 사용 기술 |
|---|---|
| 서버 | Spring Boot 3.5, Java 17, Spring Data JPA, H2 DB |
| 로그인·권한 | Spring Security 6 (세션 로그인, 비밀번호 BCrypt 암호화) |
| 화면 | Thymeleaf + **SB Admin 2** 템플릿, Chart.js(차트), DataTables(표 검색) |

---

## 2. 핵심 ① — 보안은 "두 겹"으로 지킨다

**역할 검사**와 **본인 소유 검사**를 따로 둡니다.

| 겹 | 하는 일 | 막는 것 |
|---|---|---|
| 1겹 (SecurityConfig) | "강사인가? 학생인가?" | 학생이 강사 화면에 들어가기 → **403** |
| 2겹 (Service) | "**네** 강좌인가? **네가** 듣는 강좌인가?" | 강사2가 주소 숫자만 바꿔 강사1 강좌를 열기 → **403** |

1겹만 있으면 강사끼리는 서로의 강좌·학생 명단·성적을 볼 수 있습니다. 그래서 2겹이 필요합니다.

---

## 3. 핵심 ② — 규칙은 화면이 아니라 서버에서 지킨다

> **화면에서 막는 것은 "편의", 서버에서 막는 것은 "보안"**

예를 들어 마감된 과제는 화면에서 **제출 버튼을 잠가** 두지만, 개발자도구로 잠금을 풀고 보내도 **서버가 다시 검사해서 거부**합니다.

| 규칙 | 내용 | 어긋나면 |
|---|---|---|
| B1 | 시작일시 ≤ 지금 ≤ 종료일시 일 때만 제출 | "제출 기간이 아닙니다" |
| B2 | 수강 등록한 학생만 과제 열람·제출 | 403 |
| B3 | 과제당 학생 1건, 다시 내면 덮어쓰기 | 기존 제출 수정 |
| B4 | 채점이 끝난 과제는 다시 제출 불가 | "채점 완료된 과제" |
| B5 | 강사는 본인 강좌만 수정·삭제·채점 | 403 |
| B6 | 점수는 0 이상 배점 이하 | 입력칸 오류 |
| B7 | 종료일시는 시작일시보다 뒤 | 입력칸 오류 |
| B8 | 제출물이 있는 과제는 삭제 불가 | "제출물이 있어 삭제 불가" |

오류를 보여 주는 방법도 두 가지로 나눴습니다. **입력이 잘못됐으면 그 칸 아래에 빨간 글씨**(B6, B7), **규칙에 걸렸으면 화면 위에 알림**(B1, B4, B8)입니다.

## 4. 핵심 ③ — 데이터는 5개의 표, "계산할 수 있는 건 저장하지 않는다"

```
사용자(USERS) ─ 강좌(COURSE) ─ 수강 명단(ENROLLMENT) ─ 과제(ASSIGNMENT) ─ 제출물(SUBMISSION)
```

- **수강 명단**: 학생 1명이 여러 강좌를, 강좌 1개에 여러 학생이 있는 관계라 중간에 명단 표를 둠
- **저장하지 않고 계산하는 값**: 과제 상태(예정·진행중·마감), 미제출자, 제출률, 평균 점수
  → 예: "마감" 여부를 저장하면 시간이 지날 때마다 고쳐야 하지만, **지금 시각과 비교**하면 항상 정확함
- 통계는 DB가 과제별로 묶어서 한 번에 계산(**group by**)

## 5. 핵심 ④ — 프로젝트 구조: 역할별로 층을 나눴다

요청은 **컨트롤러 → 서비스 → 리포지토리** 순서로 처리됩니다.

| 층 | 패키지 | 하는 일 |
|---|---|---|
| 화면 | `templates/` | SB Admin 2 레이아웃 1개를 모든 화면이 공유 |
| 컨트롤러 | `controller/` | 주소를 받고 화면을 고름 |
| 서비스 | `service/` | **규칙 B1~B8 검사**, 실제 처리 |
| 리포지토리 | `repository/` | DB 조회·저장 |
| 엔티티 | `domain/` | 표 구조 + "내 강좌인가?" 같은 판단 |

이렇게 나눈 이유:
- **규칙을 한곳(서비스)에 모아서** 어느 화면으로 들어와도 같은 검사를 받게 함
- 입력 폼은 엔티티를 직접 쓰지 않고 **입력 전용 객체(DTO)** 를 따로 둠 → 폼에 `역할=강사` 같은 값을 몰래 끼워 넣어도 무시됨
- 오류 종류별 예외 3개(입력칸 오류 / 규칙 위반 알림 / 없는 데이터)를 만들어 **처리 방식을 통일**

## 6. 사용 편의 기능 — 학교 LMS를 참고해서 보충

기본 요구사항을 모두 만든 뒤, **우리 학교 LMS(lms.ync.ac.kr)의 대시보드·강좌 홈·성적 화면을 참고**해서 실제로 쓸 때 편한 기능을 보충했습니다.

| 기능 | 참고한 화면 | 이유 |
|---|---|---|
| 마감 임박 · D-day | 학교 LMS "할 일" | 과목이 여러 개면 어느 과제가 급한지 한눈에 알기 어려워서, 남은 시간을 바로 보이게 했다 |
| 마감 캘린더 | 학교 LMS 캘린더 | 목록만으로는 마감이 몰린 날을 알기 어려워서, 달력으로 한 번에 보게 했다 |
| 최근 피드백 | 학교 LMS "최근 피드백" | 채점 결과를 확인하려고 과제마다 들어가 보는 게 번거로워서, 대시보드에 모았다 |
| 강좌 홈 + 내 성적표 | 학교 LMS 성적 화면 ("평가된 과제에만 근거한 계산") | 강좌별로 내 점수가 지금 몇 %인지 바로 알 수 있게 했다 |
| 점수 숨기기 ("평가 중") | 학교 LMS "교수가 평가 중입니다" | 강사가 채점을 다 끝내기 전에 일부 학생만 점수를 먼저 보는 걸 막을 수 있게 했다 (기본은 바로 공개) |
| 강좌 카드 색 | 학교 LMS 대시보드 카드 | 강좌가 많아져도 색으로 바로 구분되게 했다 |

그 밖에: 참여코드에서 헷갈리는 0·O·1·I 제외, 소문자로 입력해도 등록, 성적 CSV(엑셀) 다운로드, 비밀번호 변경, 참여코드 재발급, 표 검색·정렬

## 7. 개발하며 겪은 문제와 해결

기능마다 직접 실행·테스트하면서 찾은 문제와 해결입니다. (전체 기록: `docs/prompt-log.md`)

| 문제 | 원인 | 해결 |
|---|---|---|
| 점수를 배점보다 크게 넣으면 오류 메시지 대신 **서버 오류(500)** | 규칙 위반으로 작업이 취소(롤백)되면서, 미리 불러온 데이터의 연결이 끊김 | 실패 시 데이터를 새로 조회. **같은 구조의 숨은 버그(과제 수정)도 함께 수정** |
| 제출 현황 화면이 학생 0명일 때 **500** | 자바스크립트 `[[...]]` 가 Thymeleaf 문법과 겹침 | 해당 스크립트를 Thymeleaf가 해석하지 않게 표시 |
| 빈칸 제출 시 **오류 메시지가 두 줄** | 빈 값이 "필수"와 "형식" 검사에 동시에 걸림 | 검사 범위를 나눔 + 점검 항목 추가로 재발 방지 |

## 8. 검증과 배포

- **테스트**: 자동 테스트 17개(`./gradlew test`) + 요구사항 U1~S5·규칙 B1~B8 통합 점검 55개 (남의 강좌 접근, 개발자도구로 강제 제출 포함)
- **배포**: 실행 파일 하나(`lms.jar`)로 묶어 제출. 공개 서버용으로 DB 관리 화면을 기본으로 끄고, 할당 포트·서브도메인에 맞게 설정

## 9. 느낀 점

- 처음 프로젝트를 만들 때 Spring Initializr에 Spring Boot 4만 있어서, 강의 기준(3.x)에 맞추느라 헤맸다.
- 강사2로 주소 숫자만 바꿨더니 강사1의 강좌가 열릴 수 있다는 걸 알고, 권한을 두 겹으로 막아야 한다는 걸 알았다.
- AI(Claude)의 설명을 들으며 개념을 이해하는 데에 시간도 걸렸고 어려움이 있었다.
