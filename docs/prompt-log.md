## 2026-09-30 · U2 · SecurityConfig 적용 후 임시 계정 로그인 실패

**요청**
SecurityConfig 작성 (URL별 권한, 폼 로그인, BCrypt `PasswordEncoder` 등록).

**문제**
- 적용 후 Spring 기본 임시 계정(`user` / 콘솔에 찍힌 비밀번호)으로 로그인하면 `/login?error`.
- 비밀번호를 정확히 복사해도 실패.

**원인**
- 임시 계정은 비밀번호를 원문으로 저장.
- `BCryptPasswordEncoder`를 Bean으로 등록하면 로그인 시 입력값을 BCrypt 방식으로 비교 → 원문과 절대 일치하지 않음.

**해결**
- 임시 계정은 곧 사라질 계정이므로 고치지 않고, DB 사용자 기반 로그인으로 넘어감.
  - U4: `DataInitializer`에서 강사 계정을 `passwordEncoder.encode()`로 암호화해 저장
  - U2: `CustomUserDetailsService` 등록 → 임시 계정 자동 생성이 꺼짐

**검증**
- 서버 시작 로그에 `Using generated security password` 가 더 이상 나오지 않음.
- 강사 계정 로그인 성공, H2 콘솔에서 비밀번호가 (60자)로 저장된 것 확인.
- 같은 비밀번호인 강사 2명의 암호화 값이 서로 다름 (BCrypt salt).

## 2026-09-30 · U1 · 학번 빈칸 제출 시 에러 메시지 2줄 출력

**요청**
회원가입 폼 검증 (`@NotBlank`, `@Pattern`, `@Email`, `@Size`) 과 입력칸별 에러 메시지 표시.

**문제**
- 모든 칸을 비우고 제출하면 학번 칸에만 메시지가 두 줄로 나옴.
  ```
  학번은 숫자만 입력하세요. (최대 20자리)
  학번을 입력하세요.
  ```

**원인**
- 빈 값 `""` 이 `@NotBlank` 에도 걸리고, 정규식 `\d{1,20}` (숫자 1개 이상) 에도 걸림.
- 하나의 값이 두 규칙을 동시에 위반.

**해결**
- 정규식을 `\d{0,20}` 으로 변경 → 빈 값은 `@Pattern` 을 통과하고 `@NotBlank` 만 담당.
- 규칙마다 담당 범위를 나눔: 빈칸 = `@NotBlank`, 형식 = `@Pattern`.

**검증**
| 입력 | 결과 |
|---|---|
| `""` | 학번을 입력하세요. (1줄) |
| `20A1` | 학번은 숫자만 입력하세요. |
| 숫자 21자리 | 학번은 숫자만 입력하세요. |
| `2026001` | 통과 → 가입 완료 |

## 2026-09-30 · U3 · 403/404 에러 페이지가 빈 화면으로 보임

**요청**
`templates/error/403.html`, `404.html` 작성 (layout 적용).

**문제**
- curl 로 학생 계정 → `/instructor/courses` 요청 시 상태코드는 403 인데 HTML 내용이 비어 있음.

**원인**
- 응답이 `Content-Type: application/json` 이었음.
- Spring Boot 는 요청의 `Accept` 헤더를 보고 에러 응답 형식을 고른다.
  - 브라우저: `Accept: text/html` → 에러 페이지(HTML)
  - curl / Postman: `Accept: */*` → JSON `{"status":403, ...}`
- 코드 문제가 아니라 테스트 방법의 문제.

**해결**
- 테스트 요청에 `Accept: text/html` 헤더를 추가해 브라우저와 같은 조건으로 재확인.
- 코드 변경 없음.

**검증**
- 학생 → 강사 URL: 403 화면 (제목 "권한 없음 - LMS", 사이드바·학생 메뉴 유지)
- 없는 주소: 404 화면
- 비로그인 → 없는 주소: 로그인 페이지로 이동
- Whitelabel 기본 오류 화면 나오지 않음

**배운 점**
같은 URL 이라도 요청하는 쪽(Accept 헤더)에 따라 응답 형식이 달라진다. Postman 테스트에서 JSON 이 와도 정상.

- 이후 과제 등록·수정·삭제(`getMyAssignment`)에도 같은 방식으로 재사용.

## 2026-10-14 · I3 · 배점에 글자를 넣으면 영어 오류 메시지가 노출됨

**요청**
과제 등록 폼 (제목, 내용, 시작/종료일시, 배점) 과 검증 (`@NotNull`, `@Min`, `@Max`, B7).

**문제**
- 배점(`Integer`) 칸에 `abc` 를 보내면 입력칸 아래에 이런 문구가 나옴.
  ```
  Failed to convert property value of type 'java.lang.String' to required type 'java.lang.Integer'...
  ```
- 사용자에게 내부 자바 타입 이름이 그대로 보임.

**원인**
- `@Min`, `@NotNull` 같은 검증은 값이 **숫자로 변환된 뒤** 동작한다.
- 변환 자체가 실패(`typeMismatch`)하면 검증 어노테이션의 `message` 가 아니라 Spring 기본 영어 메시지가 나온다.

**해결**
- `src/main/resources/messages.properties` 추가 (Spring Boot 가 자동으로 읽음)
  ```
  typeMismatch.java.lang.Integer=숫자를 입력하세요.
  typeMismatch.java.time.LocalDateTime=날짜와 시간을 올바르게 입력하세요.
  ```

**검증**
| 입력 | 결과 |
|---|---|
| 배점 `abc` | 숫자를 입력하세요. |
| 배점 `0` | 배점은 1 이상이어야 합니다. |
| 종료일시 = 시작일시 | 종료일시는 시작일시보다 뒤여야 합니다. (B7) |

**배운 점**
화면의 `type="number"` 는 브라우저 편의일 뿐, 개발자도구나 Postman 으로는 글자를 보낼 수 있다. 서버 쪽 메시지도 준비해야 한다.

**내가 직접 확인한 것**
- [ ] (예: 개발자도구로 배점 input 의 type 을 text 로 바꾸고 abc 입력 → 한국어 메시지 확인)

## 2026-10-14 · I3 · 첨부파일 한글 이름이 깨져서 다운로드됨 (테스트 도구 문제)

**요청**
과제 첨부파일 업로드 / 다운로드 (`FileStorageService`, UUID 저장, 원래 이름으로 다운로드).

**문제**
- 테스트에서 `1주차 과제.txt` 를 올리고 받았더니 다운로드 이름이 깨짐.
  ```
  filename*=UTF-8''1%EF%BF%BD%EF%BF%BD...   (EF BF BD = 깨진 글자 표시)
  ```

**원인**
- 서버 코드 문제가 아니었다.
- Windows 명령창에서 curl 로 보낼 때 한글 파일명이 **UTF-8 이 아닌 인코딩**으로 전송됨 → 서버가 UTF-8 로 읽다가 깨짐.
- 실제 브라우저는 항상 UTF-8 로 보낸다.

**해결**
- 파일명을 UTF-8 바이트로 직접 넣은 요청(브라우저와 같은 조건)으로 다시 테스트.
- 코드 변경 없음. (다운로드 쪽은 처음부터 `ContentDisposition...filename(name, UTF_8)` 사용)

**검증**
```
filename*=UTF-8''1%EC%A3%BC%EC%B0%A8%20%EA%B3%BC%EC%A0%9C.txt   → "1주차 과제.txt"
```
수정 화면의 "현재 파일" 에도 `1주차 과제.txt` 로 표시됨.

**배운 점**
에러 페이지 JSON 사례(U3)와 같은 종류. 결과가 이상할 때 코드부터 고치지 말고, **테스트 조건이 실제 사용 환경과 같은지** 먼저 확인한다.

## 2026-10-14 · I4 · 제출 현황 화면 500 오류 (JS 의 `[[` 가 Thymeleaf 문법과 충돌) ⭐ AI 코드 오류

**요청**
과제별 제출 현황 표에 DataTables (검색·정렬) 적용.

**AI 가 처음 만든 코드**
```html
<script>
    $('#submissionTable').DataTable({ order: [[0, 'asc']], ... });
</script>
```

**문제**
- 수강생이 0명인 과제의 제출 현황을 열면 **500 오류**.
- 수강생이 있을 때는 상태코드 **200** 이라 정상처럼 보였지만, 실제로는 화면 아래 스크립트 부분에서 똑같이 깨져 DataTables 가 동작하지 않았음.

**원인**
- Thymeleaf 에서 `[[ ... ]]` 는 **인라인 표현식**(값을 끼워 넣는 기호)이다.
- JS 의 2차원 배열 `[[0, 'asc']]` 를 Thymeleaf 가 식으로 해석하려다 실패 → `Could not parse as expression: "0, 'asc'"`
- 표가 먼저 전송된 뒤에 오류가 나서 200 으로 보인 것.
- 고치면서 단 **HTML 주석에도 `[[ ]]` 를 썼더니** 그것도 해석되어 다시 오류 (두 번째 실수).

**해결**
- `<script th:inline="none">` → 이 스크립트 안은 Thymeleaf 가 건드리지 않음.
- 주석에서도 `[[ ]]` 기호 제거.

**검증**
- 수강생 0명 / 1명 모두 `</html>` 까지 정상 렌더링, JS 원문 그대로 유지, Thymeleaf 오류 0건.

**배운 점**
- Thymeleaf 템플릿 안의 JS 에서는 `[[`, `[(` 를 조심한다.
- **상태코드 200 만 보고 정상이라 판단하면 안 된다.** 페이지 끝(`</html>`)까지 그려졌는지 확인.

**내가 직접 확인한 것**
- [ ] (예: 제출 현황 화면에서 검색칸에 이름 입력 → 필터링 동작 확인, 열 제목 클릭 → 정렬 확인)

## 2026-10-14 · I5 / B6 · 점수 범위 위반 시 오류 메시지 대신 500 오류 ⭐ AI 코드 오류

**요청**
채점 화면 (점수 + 피드백), B6: 0 ≤ 점수 ≤ 배점 은 Service 에서 검사.

**문제**
- 배점 50 인 과제에 51점이나 -1점을 넣으면 "점수는 0 이상 50 이하" 메시지 대신 **500 오류**.
- 로그: `LazyInitializationException: Could not initialize proxy [User#3] - no session`

**원인** (AI 가 처음 짠 컨트롤러 흐름)
```
① 컨트롤러가 제출물(submission) 을 먼저 조회
② grade() 에서 B6 위반 → 예외 → 트랜잭션 롤백
③ 롤백되면 JPA 가 그동안 불러온 엔티티와 연결을 끊음 (detached)
④ 화면에서 submission.student.name 을 읽으려는데
   student 는 LAZY 라 아직 안 불러온 상태 + 연결 끊김 → 예외
```

**해결**
- 실패해서 화면을 다시 그릴 때는 **롤백 전에 꺼내 둔 엔티티를 쓰지 않고 새로 조회**.
- 같은 구조였던 **과제 수정(B7 실패)** 도 함께 수정. 그쪽은 강좌 정보가 우연히 미리 불려 와 있어서 동작하던 것이었음 (숨은 버그).

**검증**
| 입력 | 결과 |
|---|---|
| 51점 / -1점 | "점수는 0 이상 50 이하로 입력하세요." + 입력한 피드백 유지 |
| 과제 수정 종료 < 시작 | B7 메시지 정상 표시 |
| 로그 | LazyInitializationException 0건 |

**배운 점**
예외로 롤백된 뒤에는 그 전에 불러온 엔티티를 화면에 쓰지 않는다. LAZY 연관관계는 "필요할 때 불러오기" 라서, 연결이 끊긴 뒤에는 불러올 수 없다.

**내가 직접 확인한 것**

## 2026-10-14 · I6 / B5 · 강좌 없는 강사가 남의 courseId 를 넣으면 403 이 아닌 안내 화면

**요청**
통계 대시보드 `/instructor/stats?courseId=` (강좌 선택, 없으면 첫 강좌).

**문제**
- 강좌가 하나도 없는 강사2 가 `/instructor/stats?courseId=1` (강사1 강좌) 을 열면 **403 이 아니라 200** "통계를 볼 강좌가 없습니다" 화면.

**원인**
- 컨트롤러가 "내 강좌가 없으면 바로 안내 화면" 을 **B5 검사보다 먼저** 처리 → courseId 를 보지도 않음.
- 데이터가 새지는 않았지만, 다른 화면들(남의 것 → 403)과 기준이 다름.

**해결**
- courseId 를 직접 넣었으면 내 강좌가 없어도 **항상 B5 검사(`getMyCourse`)를 먼저** 하도록 조건 수정.

**검증**
- 강사2 → `?courseId=1` : 403
- 강사2 → `/instructor/stats` (courseId 없음) : "강좌가 없습니다" 안내

## 2026-10-14 · 전체 점검 · 400/500 에러에 Spring 기본 화면(Whitelabel) 노출 ⭐ AI 코드 오류

**요청**
요구사항 ID + B1~B8 전체 통합 점검 (45개 항목).

**문제**
- 45개 항목은 모두 통과했지만, 주소를 잘못 넣으면 (`/instructor/courses/abc`, `?courseId` 누락) 400 오류에 **Spring 기본 Whitelabel 화면**이 그대로 노출.

**원인 / 해결**
- 403, 404 용 페이지만 있었음 → 그 외 오류용 공통 페이지 추가.
- AI 가 처음에 `templates/error/error.html` 로 만들었는데 **적용되지 않음**.
  Spring Boot 의 오류 화면 찾는 규칙은 `error/400.html` → `error/4xx.html` → **`templates/error.html`** 이라 `error/error.html` 은 규칙에 없는 위치였음 → `templates/error.html` 로 이동.

**검증**
| 주소 | 결과 |
|---|---|
| `/instructor/courses/abc` | 400 · "오류 - LMS" · 잘못된 요청입니다 |
| `/instructor/assignments/new` | 400 · 같은 화면 |
| 없는 주소 / 권한 없음 | 기존 404 / 403 화면 유지 |

**참고: 점검 스크립트의 실패 6건도 모두 테스트 쪽 문제였음**
- 한글 값을 Windows 명령창에서 보내 인코딩이 깨짐 (첨부파일 한글 이름 사례와 같은 함정)
- 상태코드와 메시지를 붙여서 비교
- 이미 제출한 과제를 "마감 임박" 으로 기대 (기대값 자체가 틀림)
→ 테스트 코드도 틀릴 수 있다. 실패하면 **프로그램과 테스트 양쪽**을 의심한다.

**내가 직접 확인한 것**
- [ ] (예: 주소창에 /instructor/courses/abc 입력 → "잘못된 요청입니다" 화면 확인)
