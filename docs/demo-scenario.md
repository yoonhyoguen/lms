## 0. 시연 전 준비 (시연 시작 전에 끝내 둘 것)

## 1~12. 시연 순서

### 1. 학생 · 회원가입 → 로그인 → 학생 메뉴 `U1~U3`
1. [학생 창] 로그인 화면 아래 **학생 회원가입**
2. 학번 `2026001` · 이름 `홍길동` · 이메일 `hong@lms.com` · 비밀번호 8자 이상 → **가입하기**
   - (여유 있으면) 먼저 **전부 비우고 가입** → 칸마다 빨간 메시지 1줄씩
3. "회원가입이 완료되었습니다" → 로그인
4. 👉 **말할 것:** "왼쪽 사이드바에 학생 메뉴(수강 등록, 내 과제, 내 제출)만 보입니다. 강사 메뉴는 HTML 자체가 만들어지지 않습니다(`sec:authorize`)."

### 2. 학생 · `/instructor/**` 직접 입력 → `403`
1. [학생 창] 주소창에 `/instructor/courses` 입력
2. 👉 "메뉴만 숨긴 게 아니라 **SecurityConfig 에서 URL 자체를 막아서** 403 입니다."

### 3. 강사 · 강좌 개설 → 참여코드 확인 `I1`
1. [강사 창] **내 강좌** → **+ 강좌 개설** → 강좌명 `자바 웹 프로그래밍` → **개설하기**
2. 카드의 **참여코드 8자리** 복사 (또는 크게 읽어 주기)
3. 👉 "참여코드는 서버가 `SecureRandom` 으로 발급하고, 헷갈리는 0·O·1·I 는 뺐습니다."

### 4. 학생 · 참여코드로 수강 등록 `S1`
1. [학생 창] **수강 등록** → 참여코드 입력 → **등록**
2. 👉 (선택) **소문자로** 입력해도 등록된다고 언급

### 5. 강사 · 과제 등록 (기간 역전 → 에러) `I3 · B7`
1. [강사 창] 강좌 카드 클릭 → **과제 등록**
2. **종료일시를 시작일시보다 앞으로** 넣고 등록 → 빨간 "종료일시는 시작일시보다 뒤여야 합니다." (B7)
3. 날짜를 고쳐서 과제 3개 등록 (6·8번에서 배지 3종과 마감 과제가 필요)

| 과제 | 시작일시 | 종료일시 | 배점 | 용도 |
|---|---|---|---|---|
| `1주차 실습` | 어제 | **일주일 뒤** | 100 | 진행중 → 7번 제출 |
| `0주차 준비` | 지난달 | **어제** | 10 | 마감 → 8번 강제 제출 |
| `2주차 실습` | **다음 주** | 다음 달 | 100 | 예정 |

👉 "B7 은 화면이 아니라 **Service 에서** 검사해서, 개발자도구로 값을 바꿔 보내도 막힙니다."

### 6. 학생 · 과제 목록 배지 3종 `S2`
1. [학생 창] **내 과제** → **진행중(초록) · 예정(회색) · 마감(빨강)**
2. 👉 "배지는 DB 에 저장하지 않고 **시작·종료일시와 현재 시각으로 계산**합니다."

### 7. 학생 · 진행중 과제 제출 → 재제출 `S3 · B3`
1. [학생 창] `1주차 실습` → 내용 입력 (+ 파일 첨부) → **제출하기** → "제출되었습니다"
2. 내용 바꿔서 **재제출하기** → "재제출되었습니다"
3. 👉 "과제당 학생 1건이라 **새로 만들지 않고 덮어씁니다.** DB 에도 (과제, 학생) unique 제약이 있습니다."

### 8. 학생 · 마감 과제 강제 제출 (개발자도구) `B1 거부`
1. [학생 창] `0주차 준비` → 입력칸·버튼이 **잠겨 있음** ("제출 기간이 아닙니다")
2. **F12** → Elements 에서 `<fieldset disabled="disabled">` 찾기 → **`disabled` 속성 삭제**
3. 내용 입력 → **제출하기** → 빨간 알림 **"제출 기간이 아닙니다."**
4. 👉 "화면에서 막는 건 편의, **서버(`Assignment.isSubmittable()`)에서 막는 게 보안**입니다."

### 9. 강사 · 제출 현황 · 미제출자 `I4`
1. [강사 창] 강좌 → `1주차 실습` 줄의 **[제출 현황]**
2. 요약 카드(수강생 · 제출 · **미제출** · 채점 완료) + 미제출 학생 줄은 **빨간 배경**
3. (선택) **CSV 다운로드** — 추가 기능
4. 👉 "미제출자는 저장하지 않고 **수강생 명단 − 제출자**로 계산합니다."

### 10. 강사 · 채점 (배점 초과 → 거부 → 정상) `I5 · B6`
1. 홍길동 줄 **[채점]** → 점수 **101** (배점 100 초과) → **저장** → "점수는 0 이상 100 이하로 입력하세요."
2. 점수 `90` · 피드백 `잘했습니다. 예외 처리를 보완하세요.` → **저장**
3. 👉 "배점이 과제마다 달라서 `@Max` 가 아니라 **Service 에서** 검사합니다."

### 11. 학생 · 점수·피드백 확인 → 재제출 시도 `B4 거부`
1. [학생 창] **내 제출** → `90 / 100`, 피드백 확인
2. `1주차 실습` 상세 → "채점이 완료되어 다시 제출할 수 없습니다." (제출 칸 없음)
3. (여유 있으면) 개발자도구로 제출을 시도해도 → "채점 완료된 과제는 다시 제출할 수 없습니다."

### 12. 강사 · 통계 대시보드 설명 `I6`
1. [강사 창] 사이드바 **통계** → 강좌 선택
2. 카드 4개(수강생 · 과제 · **제출률** · **평균 점수**) + 차트 2개 + **과제별 평균 · 최고 · 최저 표** + **미제출자 표**(검색 · 정렬)
3. 👉 "통계는 **group by 쿼리**로 과제별 제출 수·채점 수·평균·최고·최저를 한 번에 계산합니다. 제출률은 아직 시작 안 한 과제를 빼고 계산하고, 카드 평균은 배점이 달라 100점 환산입니다."
4. (대시보드로 돌아가면) 강사 홈 카드: 강좌 · 진행중 과제 · 채점 대기 · **평균 제출률**

## 질의응답 예상 (3분)

### "이 코드가 없으면 어떤 일이 생기나요?"

| 강사님이 가리킬 만한 코드 | 없으면 생기는 일 |
|---|---|
| `Course.isOwnedBy()` / `getMyCourse()` (B5) | 강사2가 **주소 숫자만 바꿔서** 강사1 강좌의 학생 명단을 보고 과제를 수정·삭제·채점할 수 있음. SecurityConfig 는 "강사인가?"만 확인하기 때문 |
| `Assignment.isSubmittable()` (B1) | 버튼만 잠겨 있고, 개발자도구로 `disabled` 를 지우면 **마감 후에도 제출** 가능 |
| `existsByCourseIdAndStudentId` (B2) | 수강하지 않은 학생이 과제 번호만 바꿔서 **남의 강좌 과제를 보고 제출** 가능 |
| `submission.isGraded()` 검사 (B4) | 채점 후 재제출하면 **강사가 매긴 점수 위로 새 답안이 덮어써져** 점수와 답안이 안 맞게 됨 |
| `existsByAssignmentId` (B8) | 제출물이 있는 과제를 지우면 **학생 제출물과 점수가 함께 사라짐** (또는 FK 오류로 500) |
| `@UniqueConstraint(assignment_id, student_id)` (B3) | 동시에 두 번 제출하면 **같은 과제에 제출물 2건**이 생길 수 있음 (Service 검사의 마지막 방어선) |
| `"ROLE_" + role` (LoginUser) | 로그인은 되는데 `hasRole("INSTRUCTOR")` 가 `ROLE_INSTRUCTOR` 를 못 찾아 **모든 강사 페이지 403** |
| `passwordEncoder.encode()` | 비밀번호가 **원문 그대로 DB 에 저장**됨. DB 가 유출되면 그대로 노출 |
| `th:action` (폼) | CSRF 토큰이 빠져서 모든 POST 가 **403** |
| 로그아웃·삭제를 POST 로 | 다른 사이트의 `<img src=".../logout">` 하나로 **강제 로그아웃·삭제**(CSRF) |
| `th:text` (`th:utext` 아님) | 과제 내용에 넣은 `<script>` 가 **학생 브라우저에서 실행**(XSS) |
| `@Enumerated(EnumType.STRING)` | 기본값(ORDINAL)이면 enum 순서를 바꿨을 때 **강사가 학생으로 바뀜** |
| `fetch = FetchType.LAZY` | 강좌 목록만 볼 때도 강사 정보를 매번 함께 조회 (N+1) |
| `FileStorageService` UUID 이름 | 같은 이름 파일이 **덮어써지고**, `../` 로 다른 폴더에 쓰기 공격 가능 |
| `CsvWriter` 의 `'` 붙이기 | 이름이 `=1+1` 인 학생이 있으면 강사가 CSV 를 열 때 **엑셀 수식이 실행** |

### "AI 가 처음에 뭘 틀렸나요?" → `docs/prompt-log.md`

| 추천 순서 | 기록 | 한 줄 요약 |
|---|---|---|
| 1 | **I5 / B6 롤백 후 LAZY 오류** | 점수 범위 위반 시 롤백되면서 연결이 끊긴 엔티티의 LAZY 필드를 읽다 500. 실패 시 새로 조회하도록 수정, 같은 구조의 숨은 버그(과제 수정)까지 찾음 |
| 2 | **I4 DataTables `[[ ]]` 충돌** | JS 배열 `[[0,'asc']]` 를 Thymeleaf 가 인라인 식으로 해석해 500. 상태코드 200 으로 보여 놓칠 뻔함 → `th:inline="none"` |
| 3 | **U1 메시지 2줄** | 빈 값이 `@NotBlank` 와 `@Pattern`/`@Size` 에 동시에 걸림. 학번은 고쳤는데 비밀번호는 나중에 다시 발견 → 점검 항목 추가 |

### 그 밖에 나올 만한 질문
| 질문 | 답 |
|---|---|
| 배지는 왜 컬럼이 없나요? | 시간이 지나면 저절로 바뀌는 값이라 저장하면 매번 갱신해야 함. 계산하면 항상 정확 |
| 왜 Entity 를 폼에 직접 안 쓰나요? | 폼으로 `role=INSTRUCTOR` 같은 값을 끼워 넣는 조작을 막으려고. 입력 전용 DTO 사용 |
| 세션에 왜 Entity 를 안 넣나요? | 오래 유지되는 세션에 DB 와 연결 끊긴 객체·연관 데이터가 남지 않게, 필요한 값만 복사(LoginUser) |
| `save()` 를 안 부르는데 수정이 되나요? | JPA 변경 감지(dirty checking). 트랜잭션이 끝날 때 바뀐 값을 UPDATE |
| 테스트는 어떻게 했나요? | 단위 테스트 17개(`./gradlew test`) + 요구사항 ID·B1~B8 통합 점검 59개 |
